# Android 비공개 테스트 실행 안내

확인일: 2026-11-18. 개인 개발자 계정, 약 1년 전 생성. **춘천과팅 앱 생성·AAB 업로드 이력이 없음**을 사용자 답변으로 확인했다. 이 문서는 Console 입력·테스트 운영 준비이며 업로드·심사 승인·테스트 시작을 완료했다는 기록이 아니다. 새 앱 입력값은 [최초 앱 생성 안내](FIRST_APP_SETUP.md)를 따른다.

## 적용되는 테스트 요건

2023-11-13 이후 만든 개인 계정은 **최소 12명이 연속 14일 동안 비공개 테스트 참여를 선택한 상태**를 유지한 뒤 프로덕션 접근을 신청한다. 이메일 목록 등록·APK 직접 설치·내부 테스트는 이 요건을 대신하지 않는다. 14일 경과만으로 정식 출시가 승인되지 않으며, 실제 사용·피드백·개선 내용과 출시 준비 상태를 설명해야 한다. [Google 개인 계정 테스트 안내](https://support.google.com/googleplay/android-developer/answer/14151465?hl=ko)

운영상 모집 목표는 15~20명을 권장한다(공식 최소 인원은 12명). 서비스를 실제로 평가할 수 있는 만 19세 이상 대상 대학 학생을 우선 모집한다. 가짜 계정·사용하지 않는 명의로 숫자를 채우지 않는다.

## 비공개 배포 전에 완료할 것

| 항목 | 준비 상태 또는 완료 조건 |
| --- | --- |
| Console 계정 | 개인 계정 보유 확인. Console에서 신원·연락처·Android 기기 확인 등 남은 계정 작업 점검 필요 |
| 앱 식별자 | 새 앱 입력값 `kr.hyundo.chuncheondating`. 기존 앱/업로드 이력 없음 확인 완료. Console에서 등록 가능 여부를 확인하고 이 값과 AAB 패키지를 일치시킴 |
| AAB·서명 | 제출할 AAB 경로·SHA-256·versionCode·업로드 인증서 지문을 최종 빌드 기록과 대조. 디버그 APK·가상 API 빌드를 제출하지 않음 |
| 백엔드 | 해당 빌드의 실제 로그인·팀 조회·사진 저장·신청이 검증된 연결 사용. 운영 연결이면 참가자에게 실제 웹 데이터와 공유됨을 고지 |
| 테스트 사용자 | 실제 참가자의 Google 계정 목록 또는 Google 그룹 준비. 명단은 공개 Git에 넣지 않음 |
| 심사 접근 | 별도 일반 심사용 계정·가상 팀·비밀번호·접근 절차를 Console의 앱 액세스 항목에 안전하게 입력. 운영 관리자 계정·실제 회원 자료 제공 금지 |
| 등록정보 | [스토어 초안](STORE_LISTING_DRAFT.md)의 미확정 입력과 이미지 준비 완료 |
| 정책·보안 | 아래 보완 항목의 실제 구현·운영 결과를 확인한 후 제출 |

패키지 이름은 고유하고 영구적이므로 Console 생성·등록 시 오탈자를 확인한다. AAB와 증가하는 versionCode를 사용하고 Play 앱 서명 설정을 완료한다. [Google 앱 설정·번들·서명 안내](https://support.google.com/googleplay/android-developer/answer/9859152?hl=ko)

## 현재 확인된 제출 전 보완 항목

기준: `docs/MOBILE_DEVELOPMENT.md`의 2026-11-18 코드 감사. 단순 체크박스로 완료 처리하지 말고 변경 커밋·테스트·운영 절차를 연결한다.

- 개별 사용자 차단 기능: 같은 학교·학과 지인 피하기와 별개로 확인. 신고·콘텐츠 관리와 함께 점검한다. [Google UGC 정책](https://support.google.com/googleplay/android-developer/answer/9876937?hl=ko)
- 성인 이용: 약관의 만 19세 조건과 앱 접근 제한을 일치시킨다. Console의 성인 대상 설정·미성년자 액세스 제한을 확인한다. 학생증 제출만으로 연령 확인이 끝났다고 선언하지 않는다. [매칭 앱 미성년 접근 제한](https://support.google.com/googleplay/android-developer/answer/16838200?hl=ko)
- 계정 삭제: 현재 관리자 처리 대기 방식과 공개 즉시 삭제 안내가 일치하지 않는 부분을 정리한다. 정지 계정의 요청 경로, 계정·사진 삭제 처리, 예외 보관 사유·기간까지 검증한다. [앱·웹 삭제 요청 요건](https://support.google.com/googleplay/android-developer/answer/13327111?hl=ko)
- 아동 안전: 공개 기준 URL, 앱 내 신고, 처리·기관 신고 절차, 담당 연락처 준비. 성인 전용이라도 데이팅 앱 적용 여부를 건너뛰지 않는다. [아동 안전 기준](https://support.google.com/googleplay/android-developer/answer/14747720?hl=ko)
- 의존성 감사: 기존 main부터 존재한 개발 의존성 picomatch 보안 공지의 해결 상태를 확인한다. 기존 필수 audit 검사를 우회하지 않는다. 상세는 `../MOBILE_DEVELOPMENT.md` 참고.

## Console 진행 순서

1. [최초 앱 생성 안내](FIRST_APP_SETUP.md)에 따라 새 앱을 만든다. 기본 언어 한국어, 앱 유형, 배포 국가·가격, 연락처를 실제 계획과 일치시킨다. 생성만으로 비공개 테스트가 시작되는 것은 아니다.
2. 대시보드와 앱 콘텐츠에서 개인정보처리방침·앱 액세스·광고·대상 연령·콘텐츠 등급·데이터 보안·삭제·아동 안전 선언을 완료한다. 등급과 데이터 신고 답을 임의로 선택하지 않는다. [검토 준비](https://support.google.com/googleplay/android-developer/answer/9859455?hl=ko)
3. **테스트 및 출시 → 테스트 → 비공개 테스트**에서 트랙을 만들거나 선택한다. 트랙명 제안: `closed-beta`.
4. 대한민국 등 실제 테스트 국가를 지정하고 테스터 이메일 목록 또는 Google 그룹을 연결한다. 피드백 이메일/URL도 확인한다.
5. 새 버전에 검증된 서명 AAB를 넣고 릴리스 노트를 작성한다. Console 경고·오류와 게시 개요를 확인하고 검토에 제출한다. 검토·게시 시간은 확정하지 않는다.
6. 버전이 대상 테스터에게 제공되는 상태가 된 뒤 **참여 링크를 Console에서 복사**한다. 링크를 추정하여 배포하지 않는다. [테스트 트랙 설정](https://support.google.com/googleplay/android-developer/answer/9845334?hl=ko)
7. [테스터 안내](TESTER_GUIDE.md)에 실제 링크·기간·피드백 창구를 채워 전달한다. 본 문서 작성 과정에서 메시지를 발송하지 않았다.

내부 테스트를 먼저 사용한 사람이 비공개 트랙으로 이동할 때는 내부 테스트 참여를 종료하고 비공개 참여를 선택해야 한다. [Google 트랙 전환 안내](https://support.google.com/googleplay/android-developer/answer/9845334?hl=ko)

## 14일 운영 기록

시작일은 문서 작성일이 아니라 Console의 실제 참여 상태로 판단한다. 참여자별 이메일·정확한 참여 시각은 접근 제한된 명단에 보관하고, 아래 보고에는 임의 식별자만 사용한다.

| 기록 | 입력 |
| --- | --- |
| 트랙·versionCode·배포일 | 미정 |
| 참여 링크·피드백 창구 | 미정 |
| 연속 참여 조건을 충족한 인원 | Console 확인 후 입력 |
| 테스트 기기/Android 버전 | 개인정보 없는 기기 모델·OS 버전 |
| 발견한 문제 → 수정 버전 → 재검증 | 실제 확인한 결과만 기록 |
| 실제 피드백·반영한 개선 | 비식별 요약 |
| 프로덕션 접근 신청 가능 상태 | Console 표시를 확인 |

매일 로그인 횟수를 인위적으로 늘리기보다 가입·팀·사진·신청·복귀·업데이트 등 실제 흐름을 나눠 검증한다. 사용하지 않은 기능을 테스트했다고 쓰거나 참여 기록을 만들어내지 않는다. 접근 신청 때 모집 방식·사용 상황·피드백·개선·출시 준비를 이 기록으로 설명한다. [Google 신청 안내](https://support.google.com/googleplay/android-developer/answer/14151465?hl=ko)
