# Google Play 데이터 보안 작성 검토표

확인일: 2026-11-18. 로컬 코드·SQL 기준의 **제출 전 검토용 문서**이다. 운영 DB·SDK 제공자 설정·실제 삭제 결과를 모두 확인한 상태가 아니므로 Console 답안을 자동 확정하지 않는다. 아래 자료에는 실제 회원 정보·비밀번호·API 키를 넣지 않는다.

비공개 테스트 앱도 데이터 보안 양식을 작성해야 한다. 기기 밖으로 전송하는 정보가 검토 대상이며, 개발자가 제어하는 WebView의 수집도 포함한다. 단순히 ‘네이티브 SDK가 없다’거나 ‘비공개 Storage다’라는 이유로 미수집을 선택할 수 없다. 내부 테스트만 제공하는 경우의 예외를 비공개 테스트에 적용하지 않는다. [Google 데이터 보안 작성 안내](https://support.google.com/googleplay/android-developer/answer/10787469?hl=ko)

## 데이터 흐름과 Console 분류 후보

‘분류 후보’는 현재 양식의 정확한 정의와 실제 빌드를 대조하기 위한 메모다. 수집·공유 여부, 필수/선택, 암호화, 목적에 대한 최종 선언은 운영자 검토 후 확정한다.

| 데이터 / 코드에서 확인한 항목 | 기기 밖 전송·보관 | 목적과 접근 범위 | 분류 후보·확인할 점 |
| --- | --- | --- | --- |
| 계정: 아이디, 비밀번호, Auth UUID, 이름 | Supabase Auth 가입·로그인 및 `profiles`. 비밀번호는 인증 요청에 포함되며 이 문서에서 서버 내부 저장 방식을 단정하지 않음 | 인증·계정 관리. 세션 토큰은 기기 저장 후 인증 요청에 사용 | 개인 정보의 이름·사용자 ID 등. 아이디에서 생성하는 내부용 이메일을 사용자의 실제 이메일 수집과 혼동하지 않음 |

## 새 연령 입력과 기기 안에만 남는 정보

`src/components/common/NativeAgeGate.tsx`의 현재 Android 경로는 생년월일을 React 상태에서 계산에 사용한 뒤 지운다. 생년월일을 저장하거나 서버로 보내는 코드가 없다. 저장하는 값은 `cc-native-adult-confirmation`의 **정책 버전(`19plus-v1`)과 확인 시각**이다. 미성년 입력 시 이용 화면으로 진행하지 않지만 본인 입력에 따른 확인이며 신원·연령 인증을 보장하지 않는다.

따라서 이 입력 자체를 서버 수집 생년월일로 설명하지 않는다. 반대로 학생증 사진 등에 생년월일이 포함될 가능성까지 없다고 단정하지도 않는다. 향후 분석·오류 로그·폼 자동 수집 SDK를 추가하면 생년월일 전송 여부를 다시 검사한다. 인증 세션·언어 설정 등 기기 저장 정보는 해당 값이 네트워크 요청에 실리는지 각각 구분한다.

## ‘공유’와 외부 전송 검토

- Supabase Auth·DB·Storage와 실제 사용하는 호스팅·로그 제공자의 역할, 처리 계약, 데이터 위치와 접근을 확인한다. Google 양식의 서비스 제공자 예외가 적용되는지 근거를 확인하고, 수집 사실과 공유 신고 판단을 분리한다.
- 회원이 공개하도록 선택한 팀 소개·프로필 사진과 매칭 조율용 연락처 전달은 대상·시점·동의 화면을 확인한다. 사용자 주도 전송 예외 여부를 검토하되 모든 제공을 일괄적으로 ‘공유 안 함’이라고 선언하지 않는다.
- 자체 배너도 광고 기능이다. 현재 코드의 관리자 통계와 별도로 광고주에게 회원별 데이터를 전달하는지, 배너 URL에 회원 식별자가 추가되는지, 외부 링크·리퍼러·외부 광고 SDK가 무엇을 전송하는지 확인한다.
- 현재 이 검토는 GPT/Pro 결제 등 과거 대화의 계획을 구현된 수집 기능으로 가정하지 않는다. 최종 의존성·네트워크 점검에서 발견되는 기능은 추가한다.

삭제 요청을 앱 내부와 외부 웹에서 시작할 수 있어야 하며, 실제 삭제와 정당한 예외 보관 내용을 명확히 설명해야 한다. [Google 계정 삭제 요건](https://support.google.com/googleplay/android-developer/answer/13327111?hl=ko)

검토 대상 공개 URL은 `https://chuncheon-dating5-0.vercel.app/privacy`와 `https://chuncheon-dating5-0.vercel.app/account-deletion`이다. **네이티브 연령 확인·광고 지표·차단·현재 삭제 처리 및 보관 문구의 일치, Android 내 연결, 로그인 없이 접근 가능 여부는 제출 전 확인이 필요하다.** 새 아동 안전 기준 공개 URL은 아직 미정이다.

## Console 답안 확정 순서

1. 제출할 AAB의 버전·커밋·환경, 실제 적용한 DB migration, 포함된 SDK 목록을 고정한다.
2. 가상 회원으로 가입·학생증·사진·팀·매칭·신고·후기·광고·차단·탈퇴 흐름의 전송 필드와 서버 저장을 확인한다. 민감한 응답 본문·토큰은 로그/보고서에 남기지 않는다.
3. 위 표의 각 항목별로 Google 데이터 유형, 수집/공유, 필수/선택, 목적, 일시 처리 여부를 결정한다. 사진 공개/서버 저장 및 실제 이름/닉네임의 차이를 반영한다.
4. 전송 암호화는 HTTPS 주소뿐 아니라 모든 SDK·외부 링크·실제 요청을 확인한다. 저장 암호화 또는 특정 보안 인증을 확인 없이 추가 주장하지 않는다.
5. 삭제 요청·파일 정리·예외 보관과 공개 정책을 맞추고 데이터 삭제 관련 질문을 작성한다. 공개 지원 이메일 후보 `john_1217@naver.com`의 수신·담당자·실제 처리 가능 여부를 확인한다.
6. 운영자가 답안을 검토하여 확정하고 Console 미리보기와 실제 서비스 설명을 대조한다. 이후 수집 목적·SDK·보관 기간·기능이 바뀔 때 다시 검토한다.
