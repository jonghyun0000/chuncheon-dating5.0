# 같은 학교·학과 지인 피하기 — 적용 전 검토

2026-10-12. 사용자 운영 적용 승인. `release/department-privacy`는 운영 main에서 분기하여 지인 피하기만 포함한다. 팀원 모집과 프로 유료화는 포함하지 않는다.

## 동작

마이페이지 및 팀 등록/수정/현재 팀 화면에서 선택하는 계정 설정. 기본 꺼짐. 저장 성공 응답 이후에만 켜졌다고 표시하며, 조회/저장 실패 시 재조회 전까지 편집을 막는다. 저장된 active/matched 팀과 비공개 초안 및 기존 신청에 연결된 종료 팀의 전체 팀원 학교·학과를 비교한다. 한쪽 소유자만 설정해도 일치하는 상대 팀 전체를 양방향 숨긴다. 동일 학과이면서 다른 학교는 보인다. 학교/학과의 공백과 대소문자를 정규화하며, 학과 별칭이나 개편 전후 학과는 추측해 합치지 않는다. 팀원은 별도 계정 연결 없이 대표자가 등록하는 기존 모델을 유지한다.

프로필에는 학과 필드가 없어 팀/초안 정보가 없는 계정의 학과를 판별할 수 없다. UI에서 저장된 팀 정보가 필요하다고 안내한다. 이미 다운로드한 사진·확인한 정보는 회수할 수 없다. 관리자에게는 기존 권한/MFA 기준으로 계속 보인다.

## 서버 보호

- 소유자만 조회 가능한 설정 테이블. 직접 쓰기 권한 없음. 인증된 활성 사용자가 자기 설정만 변경하는 RPC.
- 비공개 스키마의 비교 함수는 클라이언트 실행 권한 없음. 보안 함수의 search_path 고정.
- 홈 RPC와 명단 뷰의 권한 함수에 서버 필터. teams/match_requests SELECT에는 제한적 RLS를 추가하여 다른 허용 정책으로 우회할 수 없게 한다.
- 기존 사진 RPC 및 Storage 읽기도 명단 권한을 통해 차단된다. 연락처의 기존 비공개 정책 유지.
- 매칭 신청/수락은 동일한 서버 조건을 재검사. 설정 변경은 기존 매칭과 같은 팀 잠금 순서를 사용한다.
- 신규 설정은 모두 꺼짐. 기존 팀/신청/사진 데이터는 삭제하거나 상태를 바꾸지 않는다.

## 적용 순서와 복구

1. 실제 로컬 Supabase Auth/PostgREST/Storage 통합 검사 완료, 테스트 결과와 운영 적용 승인을 확인한다.
2. 운영 최신 스키마/마이그레이션 이력과 백업을 확인한다. 팀원 모집/프로 변경이 없는지 배포 범위를 확인한다.
3. 트랜잭션으로 `20261012051216_department_privacy.sql` 적용. lock_timeout 5초/statement_timeout 30초. 잠금 또는 오류 시 전체 롤백.
4. 프런트 배포 후 비운영 테스트 계정으로 켜기/끄기와 기존 가입·팀·매칭 경로 확인.
5. 프런트 문제 시 이전 배포로 되돌리되 서버 보호는 유지한다. 켜진 사용자의 보호를 무단 해제하는 DB 롤백은 하지 않는다. 서버 문제는 우선 수정/안전한 서비스 제한 후 승인된 복구로 처리한다.

## 검증 제한

PostgreSQL 17 회귀 검사는 실제 SQL/RLS를 실행하지만 Auth/Storage는 테스트 스텁이다. 브라우저 검사는 API 모킹이다. 실제 로컬 Supabase 통합 스크립트에도 새 켜기/조회/신청차단/끄기 시나리오를 추가했다. 이번 작업에서는 이전 Docker 공간 오류 없이 실제 로컬 스택을 실행했고, 인증·PostgREST·Storage 연동도 검증했다. 운영 사용자 데이터로 테스트하지 않는다.
