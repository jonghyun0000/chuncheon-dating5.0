# 학생증 사진 제출 후 즉시 이용 — 운영 적용 대기

2026-10-14. 기준 운영 커밋 `35427ebd5e326412ca8f7e6e3326582cec82d0e3`.
운영 DB는 집계 및 함수 정의 조회만 수행했다. 아래 migration은 아직 적용하지 않았다.

## 동작

| 회원 상태 | 서비스 이용 | 인증 배지 |
|---|---|---|
| 신규 가입, 사진 없음 | 가입 완료 불가 | 없음 |
| 사진 제출, 최초 심사 대기 | 팀 공개·신청·수락·사진 등 기존 기능 이용 | 없음 |
| 관리자 승인 | 이용 가능 | 표시 |
| 관리자 거절 | 마이페이지·학생증 정정·계정 관리로 안내, 참여 차단 | 없음 |
| 거절 후 재제출 | 재승인 전까지 제한 유지 | 없음 |
| 재승인 | 이용 재개 | 표시 |
| 별도 계정 정지/탈퇴 | 승인 여부와 무관하게 기존 제한 유지 | 참여 불가 |

이미지 파일 형식과 크기를 검사한다. 실제 학생증인지 자동 판정하지 않는다. 학생증 파일은 비공개이며 본인과 관리자만 접근한다. 상대 연락처는 기존처럼 직접 공개하지 않고 관리자 매칭 안내 방식을 유지한다.

기존 사진 미제출 회원은 둘러보기와 비공개 초안 작성이 가능하며, 사진을 제출하면 승인 전에도 참여할 수 있다. 이미 승인된 기존 회원의 참여 권한을 보존한다. 운영 집계 조회 당시 활성 사진 미제출·대기 회원은 11명, 활성 거절 회원은 3명이다. 적용 시 기존 거절 회원도 제한되며 다시 제출하도록 안내한다. 숫자는 배포 전에 다시 확인한다.

## 구현 및 권한

- 가입 화면에 눈에 보이는 필수 사진 첨부 칸, 파일명·형식·용량·비공개 안내를 표시한다. 사진이 없거나 형식이 잘못되면 Auth 계정을 생성하기 전에 중단한다.
- 서버도 프로필 생성 시 본인 Storage 경로의 실제 파일 존재를 확인한다. 기존 중단된 가입 복구 및 업로드 결과가 불확실할 때 파일 보존 처리를 유지한다.
- `verification_restricted`는 거절 이력을 재제출 후에도 유지한다. 본인이 직접 해제하거나 인증 상태를 승인으로 바꿀 수 없다.
- `is_active_user`, `can_participate`, 홈 목록, 명단 조회, 기존 요청/매칭 관계의 SELECT 정책이 거절된 계정과 상대 팀 노출을 제한한다. 팀/매칭을 삭제하지 않으므로 승인 후 다시 확인할 수 있다.
- 기존 같은 학교·학과 지인 피하기, 팀 사진 비공개 저장·보관, 관리자 MFA를 유지한다.
- 관리자 심사 UI는 검토한 파일 경로가 그대로일 때만 승인/거절한다. 도중에 다른 사진이 제출되면 새로고침을 안내한다.
- 가입·소개·학생증 안내 및 서비스 설명을 4개 언어에 반영한다. 기존 약관 동의 버전은 유지한다.
- 관리 상태 변경은 서버에서 이후 요청부터 반영된다. 이미 표시하거나 저장해 둔 사진을 회수할 수는 없다. 화면은 다시 방문/새로고침 및 기존 프로필 갱신 시 최신 상태를 반영한다.

- 테스트에는 가상 계정/사진만 사용했다. 운영 가입·매칭·사진은 테스트하지 않았다.

## 적용 순서 및 중단 조건

1. 운영 main/배포가 기준 이후 변경되었는지, 함수 정의와 migration 이력이 달라졌는지 재확인한다. 달라졌으면 먼저 재검토한다.
2. 현재 배포와 관련 함수·정책을 백업하고 이 브랜치 프론트엔드를 사전 빌드한다. DB 설정을 바꿔가며 운영 사용자로 테스트하지 않는다.
3. 승인된 작업 시간에 `supabase/migrations/20261014060428_photo_first_open_access.sql` 전체를 단일 트랜잭션으로 적용하고 즉시 준비된 프론트엔드를 전환한다. lock timeout 5초, statement timeout 30초. 잠금/오류 시 중단한다.
4. DB와 프론트엔드는 별도 시스템이므로 완전히 원자적으로 전환되지는 않는다. 전환 간격을 최소화한다. 이전 회원가입 탭에는 파일 입력이 없어 새로고침이 필요하다. 이때 생성만 된 Auth 계정은 기존 '가입 이어하기'로 복구할 수 있다.
5. 운영 배포 커밋·공개 페이지·응답 상태를 읽기 전용으로 확인한다. 관리자 인증관리에서 안내와 본인 권한을 확인하고, 개인정보 없이 오류율을 관찰한다. 운영 신규 가입/매칭을 자동 테스트하지 않는다.
6. 기존 migration은 재실행하지 않는다. 특히 학과 지인 피하기 migration은 로컬 파일과 운영 적용 타임스탬프가 다르다.

DB 오류, 사진 업로드 실패 증가, 기존 승인 계정 참여 실패, 지인 피하기/파일 권한 회귀가 확인되면 추가 작업을 중단하고 복구한다.
