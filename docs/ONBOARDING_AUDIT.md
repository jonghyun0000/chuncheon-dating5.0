# 춘천과팅 가입·팀 등록 흐름 개선

기준: 2026-10-12 운영 main `e4d87607dbbf281f8ef62459cd6eef10ca5a1048`, Supabase `slddnhyvstfvobxxcazt` 읽기 전용 조사. 운영 DB 변경 없음.

## 확인한 문제와 우선순위

1. 상태와 다음 행동: 학생증이 제출된 심사 대기자에게도 배너가 ‘학생증 다시 제출’을 표시했다. 승인된 비공개 초안에는 공개 버튼이 있지만, 승인과 공개가 서로 다른 단계라는 설명이 부족했다. 공개 후 첫 신청으로 연결되는 안내도 홈 이동 버튼뿐이었다.
2. 작성 내용 보호: 팀 폼은 React 메모리에만 있고, 링크·뒤로가기·수정 취소·새로고침 전 경고가 없었다. 저장 전 이동하면 입력과 아직 업로드하지 않은 사진을 잃는다.
3. 오류 수정: 입력 오류는 폼 맨 아래에 표시되며 문제 입력칸으로 포커스를 옮기지 않았다. 3~4명 입력 시 긴 화면에서 수정 위치를 찾기 어렵다.

위 동작은 소스와 가상 회원 브라우저 테스트로 확인했다. 실제 사용자가 이 때문에 이탈했다는 인과관계와 개선 효과는 미측정이다.

## 이미 구현된 흐름

- 학생증 없는 가입·둘러보기·초안 저장, 별도 인증 제출 화면.
- 서버 승인 확인 후 명시적으로 초안 공개. `publish_my_team_draft`가 본인 초안과 `can_participate`를 검증한다.
- 사진은 닉네임 아래 팀원별 선택 1장, 마지막 동의 후 업로드. 사진 없이 저장 가능.
- 사진 업로드 부분 실패 시 성공분 재사용, 실패 사진 제거 후 저장 가능.
- 신청함의 보낸/받은/매칭완료 구분, 빈 목록 및 읽기 실패 재시도.
- 관리자 접근 분리와 양 성별 조회, 회원에게 연락처 비공개.

## 이번 변경

- 심사 대기 배너를 ‘심사 상태 확인’으로 변경하고 중복 제출이 필요 없음을 안내. 인증 화면에서는 잘못 제출한 경우의 교체 기능은 유지한다.
- 승인된 초안에는 ‘공개 버튼을 눌러야 노출됨’, 공개 팀에는 같은 인원수 팀 탐색·신청함 안내를 제공한다.
- 앱 내 이동·뒤로가기·수정 취소에 계속 작성/저장하지 않고 나가기 대화상자. 새로고침·탭 닫기에는 지원 브라우저의 기본 경고. 저장 성공 후 해제, 실패 시 유지.
- 소개글·학과·학번·닉네임·연락처 오류를 입력칸 옆에 표시하고 첫 오류로 포커스/스크롤 이동. 취향·동의 오류도 해당 위치로 이동.
- 4개 언어 안내 제공. 공식 React Router `useBlocker`를 사용하기 위해 최상위 라우터만 Data Router로 전환하고 기존 경로·보호 컴포넌트는 유지한다.

## 남은 한계 / 후속 후보

- 자동 임시 저장은 추가하지 않았다. 사용자가 나가기를 확정하거나 OS가 앱을 강제 종료하면 미저장 내용은 복구할 수 없다. 특히 모바일 beforeunload는 브라우저·OS에 따라 표시되지 않을 수 있다.
- 사진을 유지한 단순 소개글 수정에도 사진 재동의가 필요한 기존 동작은 유지한다. 현행 사진 조회 RPC가 동의 버전을 반환하지 않으므로, 버전 확인·갱신·권한 테스트를 포함하는 별도 변경으로 다룬다. 현재의 동의 요구를 단순히 우회하지 않는다.
- 사진 없이도 가능하다는 기존 최종 동의 문구는 유지한다. 추가 홍보 문구 실험은 이번 범위에 넣지 않는다.
- 작성 인원수를 줄일 때 제거되는 팀원 입력에 대한 별도 복구 기능은 없다.
- 라우터 기능 추가로 초기 JS gzip 약 19KB 증가. 단순 청크 분할로 총 전송량 감소라고 주장하지 않는다.

## 측정 계획

`supabase/diagnostics/onboarding_snapshot.sql`은 관리자 실행용 읽기 전용 집계이며 앱에 노출하거나 스케줄링하지 않는다. 활성 일반 회원 ID를 내부적으로 중복 제거하고 합계만 출력한다.

확인 시점: 활성 일반 회원 125, 남아 있는 팀/초안 소유자 20, 학생증 경로가 남은 회원 120, 현재 승인 회원 122, 남아 있는 공개 팀 소유자 20, 남아 있는 신청 기록의 발신 팀 소유자 11.

이 수치는 역사적 전환율이 아니다. 팀 삭제·초안 공개 후 삭제·탈퇴·학생증 보관 변경 때문에 과거 완료 기록이 사라질 수 있고, 기존 승인 회원이 현재 학생증 파일을 보유하지 않을 수도 있다.

| 단계 | 기존 근거 | 한계 |
|---|---|---|
| 가입 완료 | profiles.created_at 및 등록된 프로필 | Auth만 생성되고 프로필 생성 실패한 가입은 제외 |
| 팀 저장 | teams/team_drafts의 소유자, created_at | 삭제한 팀 및 과거 초안의 최초 저장 시점 복원 불가 |
| 인증 제출 | profiles.student_id_image_path 존재 여부 | 최초 제출 시각 없음, 경로는 집계 출력하지 않음 |
| 팀 공개 | teams.created_at | 삭제 이력은 제외 |
| 첫 매칭 신청 | match_requests.created_at의 소유자별 최소값 | 보존된 기록 중 최초이며 삭제 이력은 제외 |

우선 배포 전후 동일 SQL로 현재 상태를 비교하되 일별 차이를 전환율로 부르지 않는다. 정확한 가입 주차별 7일 전환율·단계 소요시간을 측정하려면 이후 별도 승인된 서버 이벤트 설계가 필요하다. 제안: 단계 열거형·서버 시각·서비스 전용 가명 키만 수집, 첫 완료 (가명키,단계) UNIQUE로 중복 방지, 원시 이벤트 90일 후 삭제·비식별 일별 합계만 1년 보관, 관리자 전용 RLS, 연락처·학번·사진 경로·입력 내용 수집 금지. 이번에는 이벤트나 분석 SDK를 추가하지 않았다.
