# 같은 성별 팀 구경하기 — 운영 적용 전 검토

2026-10-14. 운영 DB와 배포는 변경하지 않음. 로컬 구현·검증 완료 후 사용자 승인 대기.

## 사용자 흐름

홈 팀 목록 아래 `같은 성별 팀 구경하기` → `/team-examples`.
로그인한 활성 회원이 같은 성별의 다른 공개 모집 팀을 참고한다.
사진·연락처·매칭 신청 없이 소개글, 인원수, 인증 상태, 팀원별 학교·학과·흡연 여부·관심 태그를 표시한다.
이름·닉네임·학번도 반환하지 않고 `팀원 1`처럼 표시한다. 글은 일반 텍스트로 렌더링한다.
빈 목록, 조회 실패/재시도, 20개씩 더 보기, 팀 작성 화면으로 이동을 제공한다. 한국어·영어·일본어·중국어 문구 포함.

## 접근 경계

- 공개 API `get_same_gender_team_examples(integer,integer)`는 invoker이며 authenticated에만 실행 허용.
- 비공개 `team_examples` 스키마의 definer 함수가 명시적 인증·활성 상태·성별·팀 상태·팀 소유자 참여 가능 여부를 검사한다. search_path는 비어 있고 모든 테이블을 완전 수식한다.
- 사진 경로, 사진 ID, 연락처, 소유자 UUID, 이름, 닉네임, 학번은 SQL 응답에 없음. 기존 팀/회원/Storage RLS는 변경하지 않는다.
- 같은 성별 매칭은 기존 서버 검사에서 계속 거부된다. UI 버튼만 숨기는 방식이 아니다.
- 기존 `department_privacy.hidden`을 재사용한다. 한쪽만 선택해도 팀원 중 학교·학과가 겹치면 팀 전체를 숨긴다. 이 참고 페이지에는 관리자 예외도 두지 않는다.
- 지인 피하기의 비교 기준은 기존과 동일한 저장된 팀/임시 팀 구성이다. 아직 학과 정보가 없는 회원에 대한 추측은 하지 않는다.
- 본인 팀, 숨김·매칭 완료 팀, 제한된 소유자 팀은 제외한다. 최초 사진 제출 후 승인 대기 팀은 현재 운영 규칙대로 포함한다.
- 서버 페이지 크기는 최대 50으로 제한하고 작성일+UUID 순으로 정렬한다. offset 페이지는 목록 변경 시 이동할 수 있으며 UI에서 중복 ID를 제거한다.
- 기존 홈 조회, 가입·학생증 제출, 팀 생성·수정, 매칭, 관리자 권한과 사진 보관은 변경하지 않는다.
- 자유 입력 소개글에 사용자가 직접 적은 개인정보까지 자동 탐지/삭제하는 기능은 이번 범위에 없다.

## 검증

- `npm run check`: 타입 검사, 105개 단위 테스트, 프로덕션 빌드 통과.
- DB: 91개 회귀 테스트 및 5개 동시성 검사 통과. 신규 10개 사례에서 허용 필드, 동성 매칭 차단, 양방향 지인 피하기, 타 학교 구분, 한 명의 중복, 익명·제한 계정 차단, 사진/Storage 차단, 페이지 나누기 확인.
- Chromium: 기존 흐름 및 신규 페이지 포함 35개 통과. 모바일/PC 캡처 확인.
- Safari 계열 WebKit: 35개 통과. 실제 로컬 Supabase Auth/PostgREST/Storage: 79개 검사 통과, 테스트 환경 정리 완료.
- 브라우저 테스트는 가상 데이터로 실행하며 실제 Supabase 요청을 차단한다. 실제 API 통합 검증도 격리된 Docker와 가상 계정만 사용한다.

## 승인 후 적용 순서

1. 현재 배포와 DB 함수·권한 상태를 읽기 전용으로 재확인한다.
2. 신규 SQL `supabase/migrations/20261014075722_same_gender_team_examples.sql`을 트랜잭션으로 적용한다. 기존 테이블 데이터 변경 없음.
3. 신규 RPC 및 익명 차단을 확인하고 이 변경만 포함한 프런트엔드를 배포한다.
4. 홈 링크, 구경 화면, 팀 작성 이동, 기존 홈·가입 흐름을 확인한다.
5. 실패 시 프런트엔드를 이전 배포로 복구한다. 새 읽기 전용 함수는 기존 서비스에 영향을 주지 않으므로 남겨도 되며, 제거하려면 `supabase/operations/rollback_same_gender_team_examples.sql` 사용.

예상 다운타임 없음. 운영에 적용하지 않았으므로 실제 회원 세션에서의 최종 확인은 승인 후 배포 단계에서 수행한다.

신규 기능 롤백 후 재적용 및 익명 실행 권한 차단을 추가로 검증했다. 실제 API 테스트의 초기 실패는 모집 중인 가상 팀에 매칭 완료 전용 종료 함수를 사용한 테스트 설정 오류였으며, 가상 팀 숨김 처리로 수정 후 전체 통과했다.
